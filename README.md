## 我在做什么

一句话：**把法律工作里"没人复核"的环节，做成机器能复核的环节。**

律所实习里最高频的三件事是检索、写法律意见、核对引用。它们的痛点是同一个：
单次产出没人交叉复核，而人工复核的成本又高到实务中常常省掉。
更麻烦的是，法律 AI 最不可接受的失败模式恰好发生在没人核对的地方 ——
**编造法条**与**漏掉核心争点**。

所以下面这几个项目都在解决同一个问题：让产出可追溯、可校验、可被下游程序化检查。

## 项目

### ⚖️ [legal-agent](https://github.com/xiaobuqiao710-cmd/legal-agent) — 四智能体法律检索工作流

把「检索 → 分析 → 写作 → 质检」拆成四个职责单一的 Agent，用结构化消息协议串起来，
每一步产出在进入下一步之前都必须通过门禁校验；质检 Agent 拥有否决权，
它的否决会打回上一环节而不是直接透传给用户。

- **结构化消息协议**：Agent 之间传的是带字段的中间产物，每条材料强制携带出处 + 条款号 + 原文摘录 —— 「不许编造」因此成为结构保证，而不是提示词叮嘱
- **每步门禁**：分析引用不存在的材料 ID、文书漏写争点，都会在进入下一步前失败
- **对抗式审计层**（借鉴 [sanjiu-core](https://github.com/silvrblt/sanjiu-core) 三审九方）：承办与对抗异席位强制杜绝自审、对抗轮次硬计数熔断、审计必须给出可执行修订方案
- **引注核验器**：LLM 只做引用抽取，判断完全确定性；编造条号会被标出并列出该法已知条号，退出码 1 可接 CI
- **预设即流程**：agent 的 persona 把「先落地北大法宝检索、再按六阶段走」写死，技能路由（分析 / 引证核验）由预设强制触发，不依赖使用者记得叫它
- 52 项测试全绿：其中 9 项是专门「注入错误输入」验证门禁会拦人，另有 14 项断言的是其它拒绝路径（熔断、打回、席位违规）

`Node.js` · `多智能体编排` · `结构化消息协议` · `MIT`

### 🎓 [resumeself](https://github.com/xiaobuqiao710-cmd/resumeself) — 秋招网申辅助中心

面向求职者的个人求职进程管理中心：岗位追踪、投递看板、截止提醒、网申资料库、
简历导出、面试复盘、Offer 对比。

核心不是某个板块，而是**对账** —— 投递状态一变，岗位卡、截止提醒、日历事件同步更新。
联动只有一个出口，所有入口都走它；否则岗位卡会永远停在旧状态，这正是早期版本的真实毛病。

数据存在**你自己的账号**里，AI 能力用**你自己的 API Key**。

`Vite 5` · `React 18` · `TypeScript` · `Supabase (Auth + RLS)` · `PWA` · `MIT`

### 🎨 [buyi](https://github.com/xiaobuqiao710-cmd/buyi) — 个人主页《小王子》3D 星球版

把作品集做成一颗能拖着看的星球：程序化生成的地形（约 2 万个三角面）、1500 颗星、
一只狐狸一朵玫瑰，四个地点对应四站内容——五间亮窗小屋是项目、两座灯塔是实习、树与石碑是教育、邮筒是联系方式。

2026-10 从上一版「纸本档案」（React + 弹簧动效，仍保留在仓库根目录、可回滚）整体重做为 Three.js 单页。
值得说的是交互与结构：四站自动巡览可被鼠标随时打断、键盘 `1–4`/`←→`/`T`/`Esc` 全通、
URL 深链跟随浏览器前进后退、面板焦点圈定、手机上下滑切站；
相机、面板、标签、导航各自成模块，编排层只剩 261 行。

`Three.js` · `WebGL` · `Vite` · `GitHub Pages` · `MIT`
